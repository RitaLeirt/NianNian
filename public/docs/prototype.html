陪伴的猫 · 悬念事项管理 · 本地优先

替你念着那些悬着的事的一只猫。

念念是一个本地优先的个人「外部前额叶」——替你盯着那些悬而未决、常卡在别人手里的事，在合适的时候提醒你该推进什么、怎么说。判断下一步靠确定性推算（进度打卡 + 模板节点 + DDL/优先级），而非 AI 瞎猜。

4核心机制 · push / pull 双视角

push：念念主动推给你；pull：你主动俯瞰看板。判断下一步 = 确定性推算，不是 AI 自由发挥。

1
记一笔

一句话说清，念念用规则先猜一版。

2
念念盯着

确定性推算紧急度（凉的天数 × 10 + 球权重 + DDL 梯度）。

→
3
到点提醒

凉够了或快逾期，桌宠冒泡附话术。

→
4
打卡

推进 / 完成，日记本自动沉淀。

紧急度公式（server/db.js）：urgency = coldDays×10 + (mine:8 / stuck:14) + (high:12) + ddlGradient(逾期100/今日60/2天内40/7天内15)

5悬念数据模型

录入红线：用户唯一必填只有那句原话，其余由念念解析 / 推断 / 默认，用户只做"确认或改"。

档字段谁来填
🟢 必填原话 / 标题（title）用户唯一必填
🔵 解析可改球在谁手里 who · 对方 person · 在等 waiting · 下一步 next_step · 截止 ddl念念自动抽，瞄一眼可改
⚪ 全默认优先级 priority · 完成 done · 凉的天数 cold_days · 状态 status默认 / 自动算

🧶 「球在谁手里」逻辑上是球场的球（ball in court，谁该动），视觉上是猫的毛线球——球在爪边=该我动、球在远处=等对方、球缠住=卡住。

6三大支撑系统（骨架）

🧩 模板生态

常见场景的悬念模板，复用只改参数。内置销售 / 自由职业 / 运营 / 通用四套。

💬 话术引擎

轻默认 + 重可选：按对方职业零输入生成得体话术，占位 {对方}{在等}{事} 实时替换。

📓 日记本

每个动作自动沉淀（记 / 推 / 完成），一键生成本周日记摘要——留存命门。

7REST API 契约

Node 内置 node:http + node:sqlite，零 npm 依赖。所有写操作带输入校验与友好错误。

方法路径说明
POST/api/parse确定性解析一句话为字段草稿
GET/api/items?view=today｜week｜all看板列表 + 三视图计数
POST/api/items新建（校验：标题非空 / who / priority）
PATCH/api/items/:id部分更新（编辑）
POST/api/items/:id/push｜complete｜restore推进 / 完成 / 恢复
DEL/api/items/:id删除
GET/api/search?q= · /api/stats · /api/archive搜索 / 统计 / 归档
POST/api/render用模板为某事项渲染话术
GET/api/journal · /api/journal/weekly日记列表 / 生成周记
GET/api/pet · /api/pet/pet桌宠状态 / 撸猫 +1

9明确不做（Non-goals）

凡是让"记事更可靠、更省力"的，优先级永远高于让"猫更可爱"的。

  • 不做塞满一切的待办 App，只盯悬念事项
  • 不做真·系统桌面挂件，就是网页里的交互猫
  • 看板不做自定义 / 拖拽 / 甘特图
  • 话术不强制建"同事画像库"
  • 不接入真实生产环境，进度靠打卡
  • 判断下一步不靠 AI 自由发挥
